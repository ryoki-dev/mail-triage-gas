# 仕様書 — 問い合わせメール自動仕分けツール

## 1. 目的

問い合わせ用メールアドレスに届くメールを、担当者が読む前に自動で分類・要約し、
「ログ」スプレッドシートに一覧化する。緊急度の高いものは Slack に即時通知する。

想定効果:
- 受信トレイを開かなくても、何がどれだけ来ているかが一覧で分かる
- 見落としと対応漏れを減らす（対応状況を1か所で管理）
- 優先度の高い問い合わせに気づくまでの時間を短縮

## 2. 処理フロー

```
時間主導トリガー（既定15分ごと）
  └─ run()
       ├─ getConfig()                     設定シート + スクリプトプロパティを読み込み
       ├─ loadProcessedMessageIds_()      処理済みメッセージID（成功行のみ）を取得
       ├─ fetchTargetThreads_()           Gmail検索クエリでスレッド取得（最大N件）
       └─ 各スレッドについて:
            ├─ 最新メッセージを取得
            ├─ 処理済みならスキップ
            ├─ callClassifier_()          Claude API で分類（構造化出力）
            ├─ appendTriageRow_()         「ログ」シートに1行追記
            ├─ applyLabels_()             （非ドライラン時）カテゴリ別＋仕分け済みラベル
            └─ notifySlack_()             （非ドライラン時）優先度が対象なら通知
       └─ writeRunLog_()                  「実行ログ」に処理サマリを記録
```

## 3. データ定義

### 3.1 スクリプトプロパティ（秘密情報・インフラ）

| キー | 必須 | 内容 |
|---|---|---|
| `ANTHROPIC_API_KEY` | ○ | Anthropic API キー |
| `SPREADSHEET_ID` | ○ | ログ用スプレッドシートのID（`initialSetup` が自動設定） |
| `SLACK_WEBHOOK_URL` | 任意 | Slack Incoming Webhook URL。未設定なら通知しない |

### 3.2 「設定」シート（業務ルール・キー/値形式）

| キー | 既定値 | 内容 |
|---|---|---|
| 対象Gmail検索クエリ | `label:問い合わせ -label:仕分け済み newer_than:7d` | 処理対象の絞り込み |
| 1回の最大処理数 | `20` | API課金・実行時間の上限制御 |
| 本文の最大文字数 | `4000` | AIに渡す本文の切り詰め長 |
| 通知する優先度 | `高` | Slack通知対象（カンマ区切りで複数可） |
| 仕分け済みラベル名 | `仕分け済み` | 完了スレッドに付けるラベル |
| 優先度の判定方針 | （文章） | AIに渡す優先度ガイドライン |
| ドライラン | `false` | true の間はGmail変更・Slack通知をせずログのみ |
| Claudeモデル | `claude-opus-5` | 分類に使うモデルID |

### 3.3 「カテゴリ」シート（分類先の定義）

`カテゴリ` 列と `説明` 列。説明はAIの判断材料として使われる。行を足し引きすれば分類先が変わる。

### 3.4 「ログ」シート（1問い合わせ = 1行）

| 列 | 内容 |
|---|---|
| 受信日時 / 差出人 / 差出人メール / 件名 | メールの基本情報 |
| カテゴリ / 優先度 | AIの分類結果 |
| 要約 / 推奨アクション | AIの生成結果 |
| 個人情報 | 本文に個人情報が含まれると判定されたら「有」 |
| 対応状況 | 初期値「未対応」。担当者が手動更新。`ERROR` は分類失敗行 |
| メッセージID | Gmail メッセージID（冪等キー） |
| 処理日時 / モデル | 監査用 |

### 3.5 「実行ログ」シート（1実行 = 1行）

開始 / 終了 / 所要秒 / 取得スレッド / 分類成功 / スキップ / エラー / 通知 / ドライラン

## 4. AI 分類（Claude API）

- エンドポイント: `POST https://api.anthropic.com/v1/messages`
- モデル: 「設定」シートの「Claudeモデル」（既定 `claude-opus-5`）
- 構造化出力: `output_config.format` に `json_schema` を指定し、応答が必ず次の形になることを保証:

```json
{
  "category": "（カテゴリシートの表記のいずれか）",
  "priority": "高 | 中 | 低",
  "summary": "3行以内の要約",
  "recommended_action": "次に取るべき行動",
  "contains_personal_info": true
}
```

- `effort: "low"` … 分類は軽いタスクなので浅い思考で十分。コストと速度を優先
- リトライ: HTTP 429 / 5xx は指数バックオフで最大2回再試行。4xx は即中断
- `stop_reason == "refusal"` の場合は例外として扱う

## 5. エラー方針

| 事象 | 挙動 |
|---|---|
| 1通の分類に失敗 | その行を `対応状況 = ERROR` でログに記録し、次のメールへ。次回実行でリトライ |
| ラベル付与 / Slack通知の失敗 | 警告ログのみ（分類結果は保存済み） |
| API キー未設定・スプレッドシート未設定 | 実行全体を中断（設定ミスのため） |
| 実行内で1件以上のエラー | 実行終了時に Slack へまとめて通知 |

## 6. 冪等性

- 一次防御: Gmail検索クエリで `-label:仕分け済み` を指定し、完了スレッドを対象から外す
- 二次防御: 「ログ」シートの成功行のメッセージIDと突き合わせ、重複処理を防ぐ
- ドライラン中はラベルを付けないため、二次防御のみで重複ログを防ぐ

## 7. 必要な OAuth スコープ

| スコープ | 用途 |
|---|---|
| `gmail.modify` | メール検索・ラベル付与 |
| `spreadsheets` | ログ記録 |
| `script.external_request` | Anthropic API / Slack への外部通信 |
| `script.scriptapp` | トリガー登録 |

## 8. 制限・前提

- Gmail の1日あたり読み取り・ラベル操作の割当量、UrlFetchApp の1日あたり呼び出し回数の
  上限（GAS のクォータ）内で運用すること。1回の処理数は「設定」で調整する。
- スレッド単位で最新メッセージのみを分類する（往復のある長いスレッドの途中経過は見ない）。
- 添付ファイルの中身は解析しない（本文テキストのみ）。
